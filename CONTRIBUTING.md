# Contributing to GitHub Literacy for Recruiters

First: **you do not need to be technical to contribute here.**

In fact, if GitHub terminology confuses you, your perspective is particularly useful. This project exists to make GitHub understandable to recruiters, sourcers, talent intelligence professionals, and other people who may never have considered themselves GitHub users.

## Ways to contribute

You can:

- Ask a question
- Tell us where an explanation is confusing
- Suggest a better analogy
- Report a broken link
- Suggest a resource for the Community Recruiting Library
- Add a sourcing exercise
- Improve recruiter-specific examples
- Correct inaccurate GitHub terminology
- Add examples of non-programming GitHub use cases
- Propose an entirely new lesson

## Option 1: Open an Issue

This is the easiest way to participate.

Use an Issue when you have a question, suggestion, resource request, correction, or idea but do not want to edit the repository yourself.

A useful Issue explains:

1. What you noticed
2. What you expected or found confusing
3. What you suggest changing, if you have an idea

## Option 2: Submit a Pull Request

Want to experience GitHub collaboration directly?

1. **Fork** this repository.
2. Make your change in your fork.
3. **Commit** the change with a short description of what you did.
4. Open a **pull request** back to this repository.
5. Explain the change and why you think it improves the project.

If those words still sound mysterious, that's okay. Start with the [GitHub vocabulary guide](02-learn-the-language/README.md) or [Community Library analogy](01-start-here/the-community-library.md).

## Contributing resources

For the [Community Recruiting Library](07-community-library/README.md), only contribute material that can legitimately be distributed or linked.

Good contributions include official documentation, open educational resources, public reports, creator-published free guides, open-source tools, and legitimate links to books or paid resources.

Do not upload copyrighted books, pirated PDFs, paywalled reports, leaked employer materials, confidential candidate information, or proprietary recruiting data.

When suggesting a resource, include:

```text
Resource name:
Creator / publisher:
URL:
Suggested shelf:
Why it is useful:
Why it is okay to share or link:
```

## A note about recruiter examples

Please do not use real candidate information in exercises without appropriate permission.

When teaching profile interpretation, prefer public figures, maintainers who are clearly participating publicly, synthetic examples, or anonymized scenarios.

The goal is to teach recruiters how to interpret public evidence responsibly, not how to turn GitHub into a surveillance exercise.

## Your contribution counts even if it is tiny

Fixing one confusing sentence is a contribution.

Adding one useful resource is a contribution.

Asking a question that reveals a gap in the curriculum is a contribution.

That is part of the lesson too: collaborative projects improve through lots of individual changes, not only giant technical contributions.
