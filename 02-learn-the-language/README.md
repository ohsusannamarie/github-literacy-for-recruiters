# Learn the Language

GitHub gets much less intimidating once the nouns stop sounding like secret programmer vocabulary.

The goal here is not memorization. It is **pattern recognition**.

For each concept, ask five questions:

1. What is it?
2. What is the recruiter analogy?
3. Why do people use it?
4. What might it tell me?
5. What should I NOT assume from it?

---

## Repository

**Plain English:** A project and the files that belong to it.

**Recruiter analogy:** A project folder with a homepage, history, collaboration tools, and an audit trail.

**Why people use it:** To organize everything related to one project.

**Recruiter signal:** The repository topic, README, ownership, activity, collaborators, and history can provide context about someone's work or interests.

**Do not assume:** That every repository on someone's profile was created by them or represents deep expertise.

---

## README

**Plain English:** The front page or instruction manual for a repository.

**Recruiter analogy:** Executive summary + project overview + user guide.

**Why people use it:** To explain what the project is, why it exists, how it works, and how others can use or contribute to it.

**Recruiter signal:** Often the fastest way to understand what a project actually does.

**Do not assume:** That a polished README proves the profile owner wrote all of the underlying work.

---

## Commit

**Plain English:** A saved checkpoint representing one or more changes.

**Recruiter analogy:** Saving a meaningful project update with a note explaining what changed.

**Why people use it:** To create a traceable history.

**Recruiter signal:** Can show contribution patterns, areas of activity, and the evolution of a project.

**Do not assume:** More commits = more skill. Ten tiny commits may represent less work than one substantial change.

---

## Branch

**Plain English:** A separate line of work created from a project so someone can make changes without disrupting the main version.

**Recruiter analogy:** Duplicate the working document, experiment safely, then decide whether to merge the changes back into the official version.

**Why people use it:** To work on features, fixes, or experiments independently.

**Recruiter signal:** Mostly contextual. Branches tell you how work is organized, not how talented someone is.

---

## Pull request

**Plain English:** A proposal to merge one set of changes into another branch.

**Recruiter analogy:** "I made these changes. Please review them before they become part of the official version."

**Why people use it:** Review, discussion, quality control, collaboration, and knowledge sharing.

**Recruiter signal:** Pull requests can be particularly useful because they may reveal collaboration, technical discussion, reasoning, review behavior, and specific contributions.

**Do not assume:** Opening many pull requests means someone is senior or highly skilled. Context matters.

---

## Issue

**Plain English:** A trackable item for a bug, idea, request, question, task, or discussion.

**Recruiter analogy:** Jira ticket + project task + discussion thread.

**Why people use it:** To coordinate work and discuss problems or ideas.

**Recruiter signal:** Issues may show domain interests, troubleshooting, maintainership, community participation, or project responsibility.

---

## Fork

**Plain English:** Your own GitHub-connected copy of someone else's repository.

**Recruiter analogy:** "Make a copy," except the copy remembers which original project it came from.

**Why people use it:** To experiment with, modify, or contribute to another project.

**Recruiter signal:** A fork can show interest or experimentation.

**Do not assume:** A fork means the person authored or materially contributed to the original project.

---

## Star

**Plain English:** A way to bookmark or publicly show interest in a repository.

**Recruiter analogy:** Save + lightweight public endorsement.

**Why people use it:** To remember useful projects or signal interest.

**Recruiter signal:** A person's starred repositories may provide clues about interests, technologies, tools, or communities.

**Do not assume:** A star means the person uses, understands, or endorses every aspect of the project.

---

## Watch

**Plain English:** Subscribe to repository activity and notifications.

**Recruiter analogy:** Follow this project and tell me when something happens.

---

## Organization

**Plain English:** A shared GitHub workspace used by companies, teams, communities, and open-source groups.

**Recruiter analogy:** Company page + shared project workspace.

**Recruiter signal:** Organization context can help you understand where projects live and who collaborates around them.

**Do not assume:** Visible organization association automatically equals employment.

---

## Contribution graph

**Plain English:** The familiar grid of colored squares on a GitHub profile showing certain types of activity over time.

**Recruiter analogy:** Activity calendar, not performance rating.

**Recruiter signal:** It can suggest patterns of public activity.

**Do not assume:** Empty squares mean someone is inactive, unemployed, or not coding. Private work may be hidden or represented differently, and many jobs do not create public GitHub activity.

---

## The rule to remember

**A GitHub signal is a clue, not a conclusion.**
