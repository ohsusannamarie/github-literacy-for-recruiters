# GitHub vs. Google Drive

The Google Drive analogy is useful because both platforms can hold files and folders. But GitHub adds a project history and collaboration model that changes how people use those files.

## Google Drive says

> Here are the files.

## GitHub says

> Here are the files, how they changed, who changed them, what people are discussing, what work is still open, and what other people have built from them.

## Side-by-side

| Google Drive | GitHub |
| --- | --- |
| Folder | Repository |
| File preview | Rendered file view |
| Version history | Commit history |
| Comment | Issue or pull request discussion |
| Make a copy | Fork |
| Shared editing | Branches + pull requests |
| Activity log | Contribution + commit history |
| Document homepage | README |

## The important difference

Google Drive is primarily **document-centric**.

GitHub is primarily **project-centric**.

That means GitHub treats change itself as important information.

A recruiter looking at a GitHub repository should not ask only:

> What files are here?

Also ask:

> What happened here?

That second question is where much of GitHub's value lives.

## Recruiter example

Imagine a talent intelligence project containing:

- target-company research
- a role taxonomy
- search strings
- market notes
- a CSV of public company data
- documentation

In Drive, you can share those files.

In GitHub, you can also see exactly how the project evolved, invite contributions, discuss proposed changes, and let others fork the project into their own version.

## Try it yourself

Click **History** on a file in this repository. Compare what you see to ordinary document version history. Pay attention to the commit messages. Those messages explain why a change was made.
