# Git vs. GitHub

These names are related, but they are not interchangeable.

## Git

**Git is the version-control system.**

It keeps a detailed history of changes to a project.

Instead of this:

```text
Talent_Map_FINAL.xlsx
Talent_Map_FINAL_v2.xlsx
Talent_Map_FINAL_v2_USE_THIS.xlsx
Talent_Map_FINAL_v2_REALLY_FINAL.xlsx
```

Git lets one project evolve through a recorded history of changes.

Each saved checkpoint is called a **commit**.

## GitHub

**GitHub is a platform built around Git.**

It adds things people need to collaborate around those changes:

- profiles
- repositories
- issues
- pull requests
- code review
- project boards
- notifications
- organizations
- publishing
- community features

## The easiest analogy

**Git = the engine.**

**GitHub = the car, dashboard, garage, roads, and community built around the engine.**

You can use Git without GitHub. You can also use much of GitHub's website without becoming a command-line Git expert.

## Why recruiters should know the difference

When you see a person's commit history, branches, or pull requests, you are seeing behaviors that come from the Git version-control model.

Understanding that model helps you interpret what happened instead of treating GitHub as a collection of static profile fields.

Open the commit history for this repository. Each entry represents a saved change to the project. Notice that the project itself stays in one place while its history accumulates behind it.
