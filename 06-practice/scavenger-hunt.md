# GitHub Recruiter Scavenger Hunt

Use any public GitHub profile you are comfortable researching. The goal is not to identify a candidate. The goal is to practice reading evidence.

## Round 1: Orientation

Find:

- the person's bio
- any linked website
- pinned repositories
- visible organizations
- recent public activity

Write down **facts only**.

## Round 2: Repository investigation

Choose one pinned or relevant repository.

Answer:

1. Is the repository owned by this person?
2. Is it a fork?
3. What does the README say the project does?
4. When was it last updated?
5. Who contributes to it?
6. What languages appear?
7. Are there open or closed issues?
8. Are there pull requests?
9. Is there evidence people use or reference the project?

## Round 3: Contribution investigation

Find one concrete contribution associated with the person.

It could be:

- a commit
- pull request
- issue
- review
- documentation change
- release
- maintained repository

Describe exactly what happened without translating it into a skill claim yet.

## Round 4: Evidence vs. inference

Create three columns:

| Evidence | Possible inference | Confidence |
| --- | --- | --- |
| | | |

Add at least five observations.

## Round 5: Catch yourself

Answer these questions:

- Did I mistake a fork for original work?
- Did I treat language statistics as a skills list?
- Did I treat contribution volume as quality?
- Did I assume organization membership meant employment?
- Did I treat stars or followers as expertise?
- Did I infer anything that the visible evidence does not support?

## Bonus: Write the outreach sentence

Write one sentence you could use in outreach that references a **specific, defensible observation** from GitHub.

Avoid:

> I saw your impressive GitHub profile.

Prefer something that demonstrates you actually looked:

> I came across your work on [project], particularly [specific contribution or theme], while mapping engineers working on [relevant domain].

The difference is context.
